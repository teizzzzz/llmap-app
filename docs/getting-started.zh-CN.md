# LLMap 入门说明（给第一次使用的人）

LLMap 是一套记录和研究「街道上的文字」（语言景观）的工具：用手机在街上拍招牌、告示、贴纸，记下位置和语言；回到电脑上整理、审核、探索，最后导出照片和数据。

这份说明讲的是**现在这个版本能做什么、怎么用**，不需要懂编程。

---

## 一、整体是怎么回事

LLMap 由两部分组成，数据通过「数据包」（一个 ZIP 文件）从手机传到电脑。

| 部分 | 用来做什么 | 在哪里用 |
|---|---|---|
| **手机 App** | 在街上拍照、框出招牌、记录位置，填写基本信息 | 手机（iOS / Android） |
| **桌面研究台** | 导入数据包，整理、审核、探索、导出 | 电脑（Windows / macOS） |

典型流程：

```
手机拍照采集 → 导出数据包 → 电脑导入 → （可选）AI 起草字段 → 逐条审核 → 导出
```

所有数据都保存在你自己的设备上，不需要账号，也不上传到云端。

---

## 二、几个先要知道的词

- **记录**：一块招牌或一段文字就是一条记录，带一张照片、位置、语言和一组研究字段。
- **裁剪图 / 原图**：原图是你拍的整张街景；裁剪图是从里面框出来的那一块招牌。平时看的是裁剪图。
- **研究字段**：对这块招牌的描述，例如主要语言、辅助语言、载体类型（看板、贴纸、海报……）、话语类型（商业、规约……）等。
- **审核状态**：一条记录整理到哪一步了——待处理、AI 草稿、已审核、已确认、需复核、已拒绝。
- **范围**：你当前在看的那一批记录。筛选、主题、关联都会改变范围；审核、AI、导出默认作用于当前范围。
- **数据包**：一个 ZIP 文件，里面是记录表和照片，用来在手机和电脑之间、或者不同电脑之间搬运资料。

## 三、桌面研究台：左侧五个入口

打开软件后，左边是固定的导航，最下面是「设置」。

### 1. 首页

打开软件先看到的页面。

- 顶部是记录总数，以及「打开资料库」「继续审核」两个按钮。
- **整理进度**：一条进度条显示已确认、已审核、待审核各有多少，下面是有位置的记录数、照片数、原图数、缺失文件数。
- **主题**：一排大卡片，每张是一组有共同特点的资料（例如「中文招牌的红」「手写的街道」）。点一张就进入资料库，只看这一组。按住卡片可以左右拖动。
- **关系画布**入口：见下面第四节。
- **主要语言构成**和**团队**：各语言的数量，以及每位采集者采了多少。点某位采集者，会进入资料库只看这个人的资料。

### 2. 资料库

整理资料的主要地方。同一批资料有四种看法，在上方切换：

| 视图 | 适合做什么 |
|---|---|
| **照片** | 像相册一样浏览，往下滚动会继续加载 |
| **表格** | 一行一条，适合对着字段核对、批量勾选 |
| **地图** | 看这批资料在街上的分布；点一个圆点打开那条记录 |
| **照片云** | 把照片按颜色、语言或字段分成一堆一堆，看整体规律 |

四种视图共用同一个范围：在照片视图里筛出来的那批，切到地图和照片云看到的也是那批。

**常用操作**

- **导入**：右上角「导入数据包」，选手机导出的 ZIP。导入完成后可以直接「审核本次导入的 N 条」。
- **筛选**：上方一行可以搜索编号或文字，按语言、状态、地区、日期筛选；「更多筛选」里有采集者、数据集和各个研究字段。生效的条件会在下面排成一行标签，点标签上的 × 可以去掉。
- **打开一条记录**：点照片（或表格的一行、地图的点、照片云里的照片），右侧会滑出这条记录的详情。
- **选中多条**：鼠标移到照片上点左上角的圆圈，或在表格里勾选。底部会出现操作条，可以对选中的这些记录审核、AI 处理或导出。
- **批量操作**：右上角黑色按钮，对「当前结果」整批进行审核、AI 处理或导出。

**照片云怎么看**

- 一开始是全貌，每一堆上面有组名和数量。画布左上角可以换分组方式（代表色、主要语言、载体类型……），选「不分组」就是一整面照片墙。
- 底部有一排分组入口，点一个就把镜头推到那一组，其他组变淡；点「全貌」回来。
- 滚轮放大，按住拖动平移。放大到足够近时，照片上会显示语言和审核状态。
- 「颜色与字段筛选」可以按颜色挑照片，或在各字段里点选；这些条件同样会出现在上方的标签行里。

### 3. 审核

逐条检查并确认记录。

- 左边是待审的照片列表，中间是大图（可切换裁剪图 / 原图，点击放大），右边是研究字段。
- 上方的文字标签切换要看哪种状态的记录（全部待审、未整理、AI 草稿、需复核……）。
- 改完字段后，在右下角选择动作：
  - **标记为已审核，下一条**（快捷键 `1`）
  - **标记为已确认**（`2`）
  - **标记为需复核**（`3`）
  - **拒绝**（`X`）
  - **只保存不改状态**（`Ctrl+S`）
- `J` / `K` 切换下一条 / 上一条。

如果是从资料库带着范围过来的（例如「审核当前结果的 80 条」），上方会显示这次审核的范围。

### 4. 导出

把资料拿出去用。上方先选导出格式：

| 格式 | 得到什么 |
|---|---|
| **分类照片**（默认） | 按某个字段把照片分成多个 ZIP，例如每种语言一个 |
| **完整数据包** | 记录加照片的完整备份，可以再导入到别的电脑 |
| **照片与 CSV** | 一个照片 ZIP，以及一张数据表 |
| **地图数据** | GeoJSON，用于在其他地图软件里显示 |

分类照片会先显示预览：每个分类有多少条记录、多少张照片。按语言分类时可以选「每种语言一个 ZIP」或「每种语言组合一个 ZIP」。按钮旁边会写明将生成几组、多少个文件。

### 5. AI 处理（可选）

让 AI 根据裁剪图先起草研究字段，之后再由人审核。

- 需要先在「设置」里填写 AI 服务的密钥；密钥只保存在这台电脑上。
- 选好对象后可以先「确认对象」（不调用 AI，只看会处理多少条），再「批量执行」。
- AI 不会覆盖已有内容，只填空白的字段；AI 写完的记录状态是「AI 草稿」，仍需要人审核。
- 完全不用 AI 也可以：在「设置」里关掉后，所有 AI 入口都会隐藏，手动整理的流程不受影响。

## 四、记录详情和关联探索

不管从哪里打开一条记录，右侧出现的都是同一个详情面板，从上到下是：

1. **照片**：点击放大；可以查看原图。
2. **基本信息**：语言、地点、采集时间、状态。
3. **操作**：「编辑字段」「选中记录」，其余（进入审核、导出、AI 处理、继续关联探索）在「更多」里。
4. **研究字段**：直接修改，改完点底部「保存」。
5. **色彩与关联**：这张照片的主要颜色，以及六种关联照片——颜色相近、同一画面、位置相近、语言相同、类型相同、颜色反差。点缩略图跳到那条记录；点「查看全部 N 张」把这一组作为新的范围打开。
6. **识别信息**：文件名、版本等，平时用不到，默认收起。

**关系画布**（从首页或详情的「继续关联探索」进入）是一块自由的画布：从一张照片出发，选一种关联方式，系统给出几张相关的照片，点其中一张加入画布，再从它继续往下走，可以分出岔路。适合顺着一个线索慢慢发现。

## 五、几条让人安心的规则

- **有未保存的修改时不会直接丢掉**：切换记录、离开页面、关闭详情或关闭窗口时，会询问「保存并继续 / 放弃修改 / 取消」。
- **改了就处处更新**：在详情或审核里保存后，照片、表格、地图、照片云里的显示会一起更新。
- **可以原路返回**：进入主题或关联后，条件行最前面有「返回……」，点一下回到之前的范围和位置。
- **条件不会被悄悄丢掉**：照片云里按颜色等筛出来的结果，切到其他视图、送去审核或导出时，仍然是那一批记录。
- **界面语言**：在「设置」里切换简体中文、日语、English。数据本身不会被翻译。

## 六、设置里有什么

- **语言**：界面语言。
- **存储**：数据存放的位置，以及照片、原图、数据库各占多少空间；可以清理旧的导入残留。
  「全部数据删除（初始化）」会清空资料库，**无法恢复**，使用前请先导出完整数据包备份。
- **导出文件夹**：导出的文件生成在哪里。
- **AI**：是否启用 AI，使用哪个服务和模型，以及密钥。
- **Backend URL**：软件内部服务的地址，一般不需要关心。

## 七、常见问题

**导入后在哪里看到这批资料？**
导入完成的窗口里有「查看本次导入」和「审核本次导入的 N 条」。之后也可以在资料库的「更多筛选 → 数据集」里选这次导入的数据集。

**照片视图里的数量比记录总数少？**
照片和照片云只显示有照片的记录。没有照片的记录在表格视图里能看到。

**地图上看不到某些记录？**
地图只显示有位置信息的记录。标题旁的「有位置的 N / 总数」会告诉你差多少。

**照片云或「色彩与关联」显示正在生成？**
第一次使用或导入新资料后，软件需要分析照片的颜色，通常几十秒。之后改字段不需要重新分析。

**界面是英文时，照片云里有些字还是中文？**
照片云内部的筛选面板和关系画布右侧栏目前只有中文和日文。

**AI 页面显示「未设置」？**
还没有在「设置 → AI」里填写密钥。

## 八、给想自己运行或参与开发的人

仓库目录：

```
app/       手机 App（Flutter）
backend/   本地服务和数据库（Python FastAPI + SQLite）
console/   桌面研究台的界面（React + Vite）
desktop/   桌面外壳（Tauri），负责启动本地服务并显示界面
docs/      文档
scripts/   构建和启动脚本
```

以开发方式启动桌面研究台：

```bash
cd desktop
npm run dev
```

数据默认保存在：

- Windows：`%APPDATA%\LLMap`
- 其中 `settings.json` 含有密钥，请不要分享或提交这个文件。

更多细节见同目录下的文档：数据格式 `data-contract.md`、Windows 构建 `windows-desktop-build.md`、macOS 构建 `macos-desktop-build.md`、界面多语言 `console-i18n.md`。
